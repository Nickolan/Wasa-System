────────────────────────────────────────────────────────────────────────────────
EPIC-03: FASTAPI BRIDGE — AUTH + VALIDACIÓN + FORWARDING
────────────────────────────────────────────────────────────────────────────────

Descripción:
  El microservicio FastAPI. Gestiona usuarios (SQLite), emite JWT, protege
  endpoints con Bearer auth, valida, aplica rate limiting y delega a n8n.

──────────────────────────────────────────────
HU-03-01: Registrar un nuevo usuario
──────────────────────────────────────────────
Título: Endpoint de registro con JWT inmediato

Historia:
  Como FastAPI Bridge,
  quiero exponer un endpoint POST /api/v1/auth/register que registre al
  usuario y emita un JWT de inmediato,
  para que el frontend pueda autenticar al usuario sin un paso de login
  adicional tras el registro.

Prioridad: Alta
Dependencias: Ninguna (backend puro)
Reglas: RN-WS-12, RN-WS-13, RN-WS-15

Criterios de Aceptación:
  - [ ] Request válido con email+password: crea usuario en SQLite, retorna 201
        con TokenResponse (access_token, token_type, expires_in).
  - [ ] Email ya existente retorna 409 Conflict (RFC 7807).
  - [ ] Email inválido retorna 400 (Pydantic EmailStr).
  - [ ] Password < 8 caracteres retorna 400.
  - [ ] La contraseña se guarda hasheada con bcrypt (passlib, rounds=12).
  - [ ] El texto plano de la contraseña NO aparece en ninguna respuesta ni log.

──────────────────────────────────────────────
HU-03-02: Autenticar usuario existente
──────────────────────────────────────────────
Título: Endpoint de login con verificación bcrypt

Historia:
  Como FastAPI Bridge,
  quiero exponer un endpoint POST /api/v1/auth/login que verifique
  credenciales y emita un JWT,
  para que un usuario ya registrado pueda iniciar sesión.

Prioridad: Alta
Dependencias: HU-03-01
Reglas: RN-WS-12, RN-WS-14

Criterios de Aceptación:
  - [ ] Request con email+password correctos: retorna 200 + TokenResponse.
  - [ ] Request con email inexistente: retorna 401 Unauthorized (RFC 7807).
  - [ ] Request con contraseña incorrecta: retorna 401 Unauthorized (RFC 7807).
  - [ ] El mensaje de error 401 NO indica cuál de los dos campos es incorrecto
        (evita enumeración de usuarios).
  - [ ] El JWT generado contiene: sub (email), exp (timestamp expiración).

──────────────────────────────────────────────
HU-03-03: Proteger /scan/start con JWT Bearer
──────────────────────────────────────────────
Título: Dependency de autenticación en endpoint de escaneo

Historia:
  Como FastAPI Bridge,
  quiero que el endpoint POST /api/v1/scan/start requiera un JWT válido,
  para que nadie sin cuenta pueda lanzar escaneos.

Prioridad: Alta
Dependencias: HU-03-01, HU-03-02
Reglas: RN-WS-11, RN-WS-14

Criterios de Aceptación:
  - [ ] Request sin header Authorization: 401 Unauthorized.
  - [ ] Request con JWT malformado: 401 Unauthorized.
  - [ ] Request con JWT expirado: 401 Unauthorized.
  - [ ] Request con JWT válido: pasa la validación y continúa al flujo de scan.
  - [ ] La dependency `get_current_user` extrae el email del payload del JWT.

──────────────────────────────────────────────
HU-03-04: Validar payload del escaneo
──────────────────────────────────────────────
Título: Validación Pydantic del cuerpo del scan

Historia:
  Como FastAPI Bridge,
  quiero validar automáticamente el payload de escaneo con Pydantic v2,
  para que ningún dato malformado llegue al sistema n8n.

Prioridad: Alta
Dependencias: HU-03-03
Reglas: RN-WS-02, RN-WS-03, RN-WS-04, RN-WS-05

Criterios de Aceptación:
  - [ ] Si target_url no es URL válida: respuesta 400 con detalle de error.
  - [ ] Si phpsessid está vacío: respuesta 422.
  - [ ] Si sqlmap_level < 1 o > 5: respuesta 400 con detalle de rango.
  - [ ] Si sqlmap_risk < 1 o > 3: respuesta 400 con detalle de rango.
  - [ ] Todos los errores siguen formato RFC 7807.

──────────────────────────────────────────────
HU-03-05: Delegar escaneo a n8n via webhook
──────────────────────────────────────────────
Título: Forwarding al Webhook Trigger de n8n

Historia:
  Como FastAPI Bridge,
  quiero reenviar el payload validado al Webhook Trigger de n8n,
  para que el workflow de orquestación comience con los parámetros correctos.

Prioridad: Alta
Dependencias: HU-03-04
Reglas: RN-WS-07

Criterios de Aceptación:
  - [ ] El payload enviado a n8n incluye: target_url, phpsessid,
        sqlmap_level, sqlmap_risk, scan_id (UUID generado).
  - [ ] Si n8n responde 200 OK: FastAPI retorna 202 Accepted.
  - [ ] Si n8n no responde o retorna error: FastAPI retorna 502 Bad Gateway.

──────────────────────────────────────────────
HU-03-06: Aplicar rate limiting por IP en /scan/start
──────────────────────────────────────────────
Título: Límite de solicitudes de escaneo por IP

Historia:
  Como FastAPI Bridge,
  quiero limitar las solicitudes de escaneo a 10 por IP por hora,
  para que no se pueda abusar del sistema.

Prioridad: Alta
Dependencias: HU-03-03
Reglas: RN-WS-06

Criterios de Aceptación:
  - [ ] Las primeras 10 solicitudes (misma IP, 60 min) se procesan normalmente.
  - [ ] La solicitud 11 recibe 429 Too Many Requests.
  - [ ] La respuesta 429 incluye header Retry-After.
  - [ ] Los límites son configurables via variables de entorno.

──────────────────────────────────────────────
HU-03-07: Retornar errores en formato RFC 7807
──────────────────────────────────────────────
Título: Respuestas de error estandarizadas

Historia:
  Como FastAPI Bridge,
  quiero que todos los errores sigan el formato RFC 7807,
  para que el frontend procese errores de forma consistente.

Prioridad: Media
Dependencias: HU-03-01, HU-03-03, HU-03-06
Reglas: RN-WS-09

Criterios de Aceptación:
  - [ ] Todos los errores incluyen: type, title, status, detail, instance.
  - [ ] Los errores 400, 401, 409, 422, 429, 502, 500 están cubiertos.
  - [ ] El handler global de excepciones FastAPI aplica el formato.
