8. FLUJO DE DATOS COMPLETO (END-TO-END)
================================================================================

  FLUJO DE AUTENTICACIÓN:
  1.  Usuario anónimo ve muro de auth en ScanFormWidget.
  2.  Hace clic en "Crear Cuenta" → RegisterModal.tsx se abre.
  3.  Completa email + password → useRegister.ts → registerApi.ts.
  4.  POST /api/v1/auth/register → AuthRouter → AuthService:
      a. Verifica email no duplicado (UserRepository.get_by_email).
      b. Hashea password con bcrypt.
      c. UserRepository.create → INSERT en SQLite users.db.
      d. AuthService.create_access_token → JWT firmado.
  5.  FastAPI retorna 201 + TokenResponse.
  6.  Frontend: authStore.login(token, email) → guarda en localStorage.
  7.  RegisterModal se cierra. ScanFormWidget detecta isAuthenticated=true
      → muestra aviso ético + ScanForm.

  FLUJO DE ESCANEO (usuario ya autenticado):
  8.  Usuario completa ScanForm y acepta checkbox ético.
  9.  useScanForm.ts → submitScan.ts.
  10. POST /api/v1/scan/start con header Authorization: Bearer <token>.
  11. FastAPI ScanRouter: Depends(get_current_user) verifica JWT → OK.
  12. ScanService genera scan_id (UUID v4).
  13. ScanService → ScanUoW → N8nRepository → POST httpx a n8n webhook.
  14. n8n responde 200 OK → FastAPI retorna 202 + ScanResponse.
  15. Frontend: mensaje éxito → redirect a VITE_DASHBOARD_URL.
  16. n8n ejecuta workflow en background:
      a. ZAP Spider → ZAP Active Scan → INSERT vulnerabilities.
      b. Nuclei scan → INSERT vulnerabilities.
      c. ffuf fuzzing → INSERT (endpoints como info).
      d. LPUSH sqlmap_tasks → Python Worker → SQLMap → INSERT vuln.
  17. Dashboard muestra resultados en tiempo real.

11. PATRONES Y CONVENCIONES
================================================================================

BACKEND (FastAPI Bridge):
  - Repository Pattern    : UserRepository y N8nRepository abstraen el
                            acceso a datos. Los servicios no conocen
                            SQLAlchemy ni httpx directamente.
  - Unit of Work Pattern  : AuthUoW gestiona la sesión SQLAlchemy async.
                            ScanUoW gestiona el cliente httpx async.
  - JWT Bearer Auth       : python-jose (HS256). Dependency FastAPI
                            (get_current_user) protege /scan/start.
                            El secreto vive SOLO en variables de entorno.
  - Password Hashing      : passlib con bcrypt (rounds=12). Nunca se
                            compara texto plano; siempre bcrypt.verify.
  - Pydantic BaseSettings : Toda configuración se lee de .env.
  - RFC 7807              : Todos los errores siguen Problem Details.
  - Fire-and-Forward      : El Bridge no espera el resultado del escaneo.

FRONTEND (React Landing):
  - FSD (Feature-Sliced)  : Capas con dependencias unidireccionales.
  - Zustand               : authStore como fuente única de verdad para
                            el estado de autenticación. Persistido en
                            localStorage con el plugin persist.
  - Axios Interceptor     : Agrega Bearer token a cada request
                            automáticamente. Limpia authStore en 401.
  - Zod + RHF             : Validación declarativa en todos los forms
                            (login, register, scan).
  - Auth Gating           : ScanFormWidget lee authStore.isAuthenticated.
                            Si false → muestra muro. Si true → muestra form.
  - Mobile-first          : Tailwind breakpoints sm → md → lg.

NOMENCLATURA:
  - Archivos Python       : snake_case.py
  - Archivos TypeScript   : camelCase.ts / PascalCase.tsx (componentes)
  - Variables de entorno  : UPPER_SNAKE_CASE
  - Endpoints REST        : /api/v1/resource/action (kebab-case)
  - Schemas Pydantic      : PascalCase (UserRegister, ScanRequest)
  - Tipos TypeScript      : PascalCase (TokenResponse, ScanRequest)
  - Stores Zustand        : camelCase con sufijo "Store" (authStore)
